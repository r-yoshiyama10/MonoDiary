## 2. 追加したい機能一覧

### 2.1 LINE から Web 日記閲覧への導線

**概要**: LINE の画面（リッチメニュー、メッセージ内のリンク、LIFF 等）から、保存された日記を確認できる **Web アプリへ遷移**できるようにする。

**狙い**: チャットに閉じず、一覧・検索・長文の読みやすい表示など Web 側の体験で振り返りしやすくする。

**検討メモ**:

- 認証は既存の **LINE Login** 方針と整合させる（深いリンク＋セッション／トークン）。
- モバイルブラウザでの操作性（戻る導線、PWA 化の要否）は別途検討。

---

### 2.2 画像の取り込み

**概要**: 現状想定のテキスト入力に加え、**画像付き**の日記エントリを許容する。

**狙い**: 写真と言葉をセットで残し、振り返りの情報量を増やす。

**検討メモ**:

- 保存先（オブジェクトストレージ等）、サイズ・形式制限、プライバシー。
- LLM 連携する場合は **マルチモーダル**（画像＋テキスト）での整文・キャプション生成の是非とコスト。
- サムネイル・EXIF の扱い（位置情報の除去など）。

---

### 2.3 AI コメントの再生成

**概要**: 生成された AI コメントが気に入らない場合、**数回に限り**再生成できるようにする。

**狙い**: 一度きりの生成に縛られず、気分に合ったコメントを得られる体験にする。

**検討メモ**:

- 「回数」の定義（1 エントリあたり上限 3 回程度、コスト上限との連動）。
- 再生成はコメントのみで、`source_text`（原文）は一切変更しない。
- 乱用防止・API コスト（レート制限と UI 上の明示）。

---

### 2.4 コメントの口調・スタイルのパーソナライズ

**概要**: ユーザーが好む AI コメントの**口調・雰囲気の傾向**を時間とともに把握し、その人に合ったコメントを生成できるようにする。

**方針イメージ**:

- **スタイル設定の保存**: YAML 等の設定ファイル、またはユーザー単位のメタデータとして **スタイルルールを蓄積**する。
- **ルールの生成・更新**: **Gemini 等の LLM** で、過去コメントへのフィードバックから傾向を要約し、システム指示に追加するスタイルガイドのルール案を作る（人手レビューまたは自動マージのどちらにするかは未決）。

**検討メモ**:

- プライバシー（学習に使うデータ範囲、削除時のルール削除）。
- ルールの衝突解決、バージョン管理、デフォルトへのリセット。
- コスト（バッチ分析 vs インクリメンタル更新）。
